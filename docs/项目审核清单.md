## 优先修复：P1

### 1. 多段压缩的中高频分频合成造成严重凹陷

- **位置：** [MultiBandCompNode.cpp:48](../SSBVoiceProcessor/Source/Nodes/MultiBandCompNode.cpp#L48)、[合成处:164](../SSBVoiceProcessor/Source/Nodes/MultiBandCompNode.cpp#L164)。
- **触发：** 启用 Multi-Band，三个 Amount 全部设为 0，Makeup 为 0；默认分频为 300/3000 Hz。
- **原因：** 中、高频使用同频率二阶低通、高通，未经相位匹配就直接相加；低频支路也没有匹配第二次分频引入的相位。
- **影响：** 即使完全不压缩，也明显改变音色。48 kHz 下的合成传递函数计算结果：2 kHz 为 −5.77 dB，2.5 kHz 为 −11.83 dB，2.8 kHz 为 −20.04 dB，3 kHz 附近约 −80.45 dB。最后一个数值是系数公式模型结果，实际浮点实现的凹陷深度会有差异。
- **修复：** 使用一致的 Linkwitz–Riley 分频结构，并对低频支路补偿后一级分频的相位。验收时检查零压缩状态下的全频扫频，确保合成幅频接近平坦。

### 2. 音频线程和界面线程并发读写普通数组

- **位置：** [AudioEngine.h:34](../SSBVoiceProcessor/Source/AudioEngine.h#L34)、[数组成员:91](../SSBVoiceProcessor/Source/AudioEngine.h#L91)、[NodeCard.cpp:203](../SSBVoiceProcessor/Source/NodeCard.cpp#L203)。
- **触发：** 音频运行期间显示频谱、瀑布图或波形。
- **原因：** 音频线程写 `spectrumBands`、`spectrumHistory`、`smoothedWave`，UI 直接读取相同的非原子元素。原子写入位置只能发布进度，不能保护后续覆盖；波形写位置还在平滑波形更新之前发布。
- **影响：** 属于 C++ 数据竞争，可能出现不一致画面和未定义行为，不能依赖“float 一次读写很小”保证正确。
- **修复：** 通过明确所有权的 SPSC 队列/快照交换传递显示数据，UI 持有独立快照。避免在实时音频线程加会阻塞的互斥锁。建议用 ThreadSanitizer 验收。

### 3. 无输入或设备中断会让自动校准界面一直卡住

- **位置：** [AutoCalibrator.cpp:8](../SSBVoiceProcessor/Source/AutoCalibrator.cpp#L8)、[AudioEngine.cpp:154](../SSBVoiceProcessor/Source/AudioEngine.cpp#L154)、[CalibrationOverlay.cpp:8](../SSBVoiceProcessor/Source/CalibrationOverlay.cpp#L8)。
- **触发：** 没有有效输入/输出设备时开始校准，或采集途中设备断开、回调停止。
- **原因：** 进度只由已采样数量推进，没有实际时间超时；`audioDeviceStopped()` 不终止采集。覆盖层拦截全部鼠标操作，又没有取消按钮，因此底下按钮里的 `cancel()` 分支无法通过鼠标到达。
- **影响：** 主界面被无限期覆盖，用户无法通过界面恢复。
- **修复：** 启动前检查可用设备和输入通道；增加无数据超时、设备停止处理和覆盖层取消入口；区分成功、取消、失败三种结果。

### 4. 限幅器之后还能增加增益，无法保证最终输出上限

- **位置：** [AudioEngine.cpp:25](../SSBVoiceProcessor/Source/AudioEngine.cpp#L25)、[OutputGainNode.h:10](../SSBVoiceProcessor/Source/Nodes/OutputGainNode.h#L10)。
- **触发：** Limiter 保持启用，在其后的 Output Gain 增加增益；其上限为 +12 dB。
- **原因：** 链路是 Limiter → Band-Limit → Output Gain；限幅后还有滤波和增益。
- **影响：** 即使限幅器本身正确，最终送往设备的信号仍可超过 0 dBFS，造成设备端削波。例如 Band-Limit 后 −1 dBFS 的样本，加 +12 dB 后成为 +11 dBFS。
- **修复：** 将最终保护限幅放在滤波和输出增益之后，并明确总旁路/模块旁路时是否保留输出保护。

## 后续修复：P2

### 5. 限幅器释放分支本身会越过阈值

- **位置：** [LimiterNode.cpp:16](../SSBVoiceProcessor/Source/Nodes/LimiterNode.cpp#L16)。
- **原因：** 用旧增益判断是否超限；如果旧增益恰好压到上限，下一步就朝 1 释放，而释放后的增益没有再次约束。
- **验证：** 原样抽取方法运行：48 kHz、阈值 −12 dB、释放 5 ms，连续输入两个 `1.0`，输出依次为 `0.251188636`、`0.254302204`；第二个样本超出设定上限约 0.107 dB。
- **修复：** 每个样本独立计算 `min(1, ceiling / abs(x))` 的允许增益上限，保证释放后的最终增益不超过该值；如需 true-peak 上限，另外加入过采样检测。

### 6. 噪声门打开时用了释放时间，容易吞字头

- **位置：** [NoiseGateNode.cpp:28](../SSBVoiceProcessor/Source/Nodes/NoiseGateNode.cpp#L28)。
- **原因：** 增益减小时使用 Attack，增益增大、门打开时反而使用 Release。门打开速度因此被默认 150 ms 释放时间控制。
- **验证：** 默认参数、1 秒静音后输入幅度 0.2 的阶跃，原方法输出增益在 5/10/50/150 ms 时分别约 0.087/0.117/0.324/0.653。
- **修复：** 分开定义检测包络和门增益的开关时间；开门使用短 Attack，关门使用较长 Release，可增加 Hold 和迟滞减少抖动。

### 7. 简单模式的宏旋钮映射不符合处理强度

- **位置：** [NodeCard.cpp:48](../SSBVoiceProcessor/Source/NodeCard.cpp#L48)、[初始化:777](../SSBVoiceProcessor/Source/NodeCard.cpp#L777)、[写回:789](../SSBVoiceProcessor/Source/NodeCard.cpp#L789)。
- **原因：** 所有参数统一按最小值到最大值线性映射，且宏初值只是各参数归一化后的平均值。
- **影响：** Compressor 调到 100% 会得到阈值 0 dB、Ratio 20、Makeup +24 dB；常见低于 0 dBFS 的信号很少被压缩，却被大幅放大。De-Esser 调到 100% 会把阈值提高到 0 dB，检测包络低于 0 dBFS 时反而不去齿音。从高级模式返回后，轻微移动宏旋钮也可能让多个参数突然跳到另一组值。
- **修复：** 为每个宏定义有方向的专用曲线，例如强度提高时降低阈值；使用明确的宏状态或相对调整，避免平均值反推造成跳变。

### 8. 实时音频处理路径中仍存在堆内存分配

- **位置：** [EqNode.cpp:29](../SSBVoiceProcessor/Source/Nodes/EqNode.cpp#L29)、[BandLimitNode.cpp:35](../SSBVoiceProcessor/Source/Nodes/BandLimitNode.cpp#L35)、[MultiBandCompNode.cpp:122](../SSBVoiceProcessor/Source/Nodes/MultiBandCompNode.cpp#L122)、[AudioEngine.cpp:157](../SSBVoiceProcessor/Source/AudioEngine.cpp#L157)。
- **触发：** 拖动滤波器旋钮，或者回调块大于现有缓冲区。
- **原因：** `Coefficients::make…()` 创建堆对象；随后把系数复制到现有滤波器，并不能消除临时对象分配和释放。缓冲区扩容也直接发生在音频线程。
- **影响：** 小缓冲、CPU 忙碌时可能发生音频中断；代码里“避免分配”的注释并未覆盖参数变化时的情况。
- **修复：** 使用无临时堆对象的系数计算，并确保目标存储已预分配；在准备阶段分配缓冲区，对更大的回调分块处理。可参考 JUCE 的 [ArrayCoefficients](https://docs.juce.com/master/structjuce_1_1dsp_1_1IIR_1_1ArrayCoefficients.html) 与 [Coefficients 工厂实现](https://raw.githubusercontent.com/juce-framework/JUCE/master/modules/juce_dsp/processors/juce_IIRFilter.cpp)。

### 9. 部分滤波参数没有按采样率约束

- **位置：** [DeEsserNode.cpp:13](../SSBVoiceProcessor/Source/Nodes/DeEsserNode.cpp#L13)、[EqNode.cpp:24](../SSBVoiceProcessor/Source/Nodes/EqNode.cpp#L24)、[MultiBandCompNode.cpp:48](../SSBVoiceProcessor/Source/Nodes/MultiBandCompNode.cpp#L48)。
- **触发：** 设备提供较低采样率，例如 16 kHz 时选择 10 kHz 高频参数；8 kHz 时默认 De-Esser 6 kHz 也已越界。
- **影响：** 频率超过奈奎斯特频率，违反 JUCE 系数函数的输入约束，可能触发断言或得到错误滤波响应。是否能选择这些采样率取决于实际设备，未进行硬件验证。
- **修复：** 统一限制频率低于采样率的一半并留余量，同时联动 UI；或明确限制支持的采样率。约束见 [JUCE IIR 实现](https://raw.githubusercontent.com/juce-framework/JUCE/master/modules/juce_dsp/processors/juce_IIRFilter.cpp)。

### 10. FFT 遇到不匹配的块大小时丢弃样本

- **位置：** [AudioEngine.cpp:89](../SSBVoiceProcessor/Source/AudioEngine.cpp#L89)。
- **原因：** 超过当前 1024 点帧的样本被忽略，变换后直接将 `fftHop` 清零，未保留余数。
- **验证：** 100 次 480 点回调共 48000 点，只有 34272 点进入 FFT；768 点回调丢掉三分之一；2048 点回调丢掉一半。256/512 点回调未触发此问题。
- **影响：** 频谱时间覆盖不连续，瀑布图速度和内容随设备缓冲大小变化；音频输出本身不因这个显示问题丢样本。
- **修复：** 用循环填满当前帧，立即变换，再将同一回调剩余样本放入下一帧；如需固定刷新率可采用明确的 hop/overlap。

### 11. 静音也会被自动校准判为成功

- **位置：** [AutoCalibrator.cpp:69](../SSBVoiceProcessor/Source/AutoCalibrator.cpp#L69)、[完成提示:55](../SSBVoiceProcessor/Source/AutoCalibrator.cpp#L55)。
- **触发：** 设备正常提供数据，但用户没有说话，或只有噪声；极短采集提前结束时也存在错误成功提示的路径。
- **原因：** 除总样本数外，没有语音有效性、信噪比、削波占比检查。纯零输入仍会写入 +6 dB 输入增益等参数，并显示“校准完成”；`peak` 计算出来后没有使用。分析函数返回 `void`，不能向调用方报告失败。
- **修复：** 分离环境静音和正常语音采集，检查有效语音时长/动态范围/削波；分析成功后再提交参数，失败时保留当前参数并提示重试。

### 12. 校准得到的噪声门阈值与实际处理电平不一致

- **位置：** [AutoCalibrator.cpp:111](../SSBVoiceProcessor/Source/AutoCalibrator.cpp#L111)、[阈值:118](../SSBVoiceProcessor/Source/AutoCalibrator.cpp#L118)、[链顺序:17](../SSBVoiceProcessor/Source/AudioEngine.cpp#L17)。
- **原因：** 噪声底来自原始输入，却在修改 Input Gain 后仍用原始噪声电平计算门阈值；门之前还经过 High-Pass。
- **影响：** 设计上的“噪声底 +8 dB”不再成立。仅考虑 +6 dB 输入增益，门实际只高于增益后的噪声底 2 dB；输入衰减时又可能过度关门。
- **修复：** 基于门输入端的信号估计噪声，或在同一电平坐标里补偿输入增益和前级处理，并检查相关模块旁路状态。

### 13. 音频设备设置缺少失败反馈和跨重启恢复

- **位置：** [PreferencesDialog.cpp:371](../SSBVoiceProcessor/Source/PreferencesDialog.cpp#L371)、[AudioEngine.cpp:38](../SSBVoiceProcessor/Source/AudioEngine.cpp#L38)。
- **原因：** `setAudioDeviceSetup()` 返回的错误被忽略；启动总是初始化默认设备，未保存或恢复设备状态。
- **影响：** 设备被占用/不支持配置时，用户不知道设置失败原因；重启会失去指定的声卡、采样率和缓冲设置。对依赖特定音频路由的使用场景尤其不便。
- **修复：** 显示具体错误、失败时恢复有效配置；成功后保存 `createStateXml()`，启动用 `initialise()` 恢复并提供回退。API 的返回值与保存恢复方式见 [JUCE AudioDeviceManager](https://docs.juce.com/master/classjuce_1_1AudioDeviceManager.html)。

### 14. 预设切换、删除后显示状态和真实处理状态不一致

- **位置：** [MainComponent.cpp:363](../SSBVoiceProcessor/Source/MainComponent.cpp#L363)、[删除:412](../SSBVoiceProcessor/Source/MainComponent.cpp#L412)、[ModuleSelector.cpp:214](../SSBVoiceProcessor/Source/ModuleSelector.cpp#L214)。
- **触发与影响：** 加载含有模块旁路的预设后，模块选择栏没有同步 `items.on`，可能显示模块开启而实际旁路；第一次右键切换也可能没有预期效果。删除当前预设后，选择框回到“默认”，DSP 参数却仍是旧预设参数。保存、加载、删除的返回值也没有反馈到 UI，失败时容易产生误判。
- **修复：** 将预设操作做成统一事务：检查结果、更新 DSP、同步全部模块图标与旋钮、更新当前预设名称；删除当前项时明确加载默认参数或显示“自定义”。

### 15. 预设名称可以越过预设目录

- **位置：** [PresetManager.cpp:10](../SSBVoiceProcessor/Source/PresetManager.cpp#L10)、[MainComponent.cpp:383](../SSBVoiceProcessor/Source/MainComponent.cpp#L383)。
- **触发：** 保存时输入含 `../`、路径分隔符或绝对路径的名称，例如 `../other`。
- **原因与影响：** 名称直接交给 `getChildFile(name + ".json")`，保存目标可能位于 Presets 目录之外，导致误覆盖其他 JSON 文件；Windows 保留名称等非法名称也没有处理。这是本地名称处理缺陷，并非已证明的远程攻击入口。
- **修复：** 只接受文件名，拒绝绝对路径、分隔符和 `.`/`..` 等特殊形式，处理 Windows 保留名称；解析后检查目标父目录必须是 Presets，并反馈覆盖/写入失败。

### 16. 预设反序列化缺少版本和类型校验

- **位置：** [PresetManager.cpp:48](../SSBVoiceProcessor/Source/PresetManager.cpp#L48)。
- **触发：** JSON 可解析，但内容不符合预设格式，例如 `{"nodes":[]}`、参数值是字符串，或文件来自未来版本。
- **影响：** 空节点数组也返回成功；版本字段只写不读；无效参数类型直接强转，且边读边修改，可能留下部分更新的状态。
- **修复：** 先检查 schema/version、节点 ID、参数类型和有限数值，再一次性提交；为旧版本提供迁移，为未知版本给出明确提示。

### 17. 工具栏宽度超过允许窗口尺寸

- **位置：** [MainComponent.cpp:233](../SSBVoiceProcessor/Source/MainComponent.cpp#L233)、[Main.cpp:29](../SSBVoiceProcessor/Source/Main.cpp#L29)。
- **验证：** 即使简单/高级按钮都只占最小 76 px，加上其他固定控件和外边距，工具栏也至少需要 1386 px；窗口默认 1360 px，最小允许 1000 px。
- **影响：** 默认尺寸就可能挤窄最右控件；缩至 1000 px 时，靠后的按钮和设置入口会被压缩至不可用。
- **修复：** 为窄窗口换行或使用溢出菜单，先为关键右侧入口保留空间；对中英文文案、1000/1360 px 和高 DPI 做布局验收。
