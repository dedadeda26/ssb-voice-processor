## 具体修改

### 1. 多段分频合成

- [MultiBandCompNode.h](../SSBVoiceProcessor/Source/Nodes/MultiBandCompNode.h) 将中高频二阶 IIR 滤波改为相互匹配的 Linkwitz–Riley 四阶滤波器，新增低频相位补偿滤波器。
- [MultiBandCompNode.cpp:15](../SSBVoiceProcessor/Source/Nodes/MultiBandCompNode.cpp#L15) 完成滤波器类型、准备与重置；低频支路增加与中高频分频合成相同的全通响应。因此三个频段不压缩时，重组后的幅频响应保持平坦。
- 分频频率按实际采样率限制在 `sampleRate * 0.45` 内；第二分频不低于第一分频。采用 LR 滤波器直接更新截止频率，移除了此处分频系数的临时堆对象。
- 这是幅度重组平坦的分频，仍会产生全通相位变化；不会把它描述成无相位变化或线性相位处理。JUCE 对该滤波器的定义见 [9.0.4 官方源码](https://github.com/juce-framework/JUCE/blob/9.0.4/modules/juce_dsp/processors/juce_LinkwitzRileyFilter.h)。

### 2. 音频与界面的显示数据同步

- 新增 [VisualizationData.h](../SSBVoiceProcessor/Source/VisualizationData.h)：使用预分配的单生产者、单消费者队列，传递 256 点波形块和 96 段频谱帧。
- 队列槽位通过 acquire/release 原子索引交接所有权。满队列时丢弃新的显示数据，不覆盖仍由界面读取的槽位，不在音频线程等待或分配内存。
- [AudioEngine.h:35](../SSBVoiceProcessor/Source/AudioEngine.h#L35) 保留原来的显示读取接口，但全部转向消息线程独占的显示历史。音频线程只向队列写入，不再修改界面正在读取的频谱、瀑布图和波形历史数组。
- [NodeCard.cpp:719](../SSBVoiceProcessor/Source/NodeCard.cpp#L719) 在界面定时器内消费队列，再触发绘制。
- 原有波形平滑外观暂时保留，并迁移到界面线程。初审中单独列出的波形平滑算法和 FFT 丢余数问题未在这一批重写。

### 3. 自动校准退出与恢复

- [AudioEngine.cpp:49](../SSBVoiceProcessor/Source/AudioEngine.cpp#L49) 记录是否存在有效输入和输出通道，采样率改为原子值。设备停止或报错时将设备标记为不可采集并终止采集。
- [AudioEngine.cpp:74](../SSBVoiceProcessor/Source/AudioEngine.cpp#L74) 让 `startCapture()` 返回是否成功；控制线程在开始/停止采集时使用 JUCE 已有的回调锁，避免清空或扩容缓冲区与正在进行的音频拷贝并发。
- [AutoCalibrator.cpp](../SSBVoiceProcessor/Source/AutoCalibrator.cpp) 启动前校验设备、时长和采样率；连续 2 秒没有采样进展，或超过目标时长加 3 秒时失败退出；设备停止、错误和提前结束均不会误进入应用参数流程。
- `onComplete` 改为带结果和原因的 `onFinished`，明确区分成功、取消、失败。样本不足会报告失败，取消/失败不应用参数。
- [CalibrationOverlay.cpp:5](../SSBVoiceProcessor/Source/CalibrationOverlay.cpp#L5) 增加取消按钮、Esc 处理以及按钮所需的鼠标与焦点设置；调整小窗口布局，避免按钮、提示与百分比重叠。
- [MainComponent.cpp:53](../SSBVoiceProcessor/Source/MainComponent.cpp#L53) 接入结果提示和覆盖层清理。延迟销毁覆盖层，保证按钮回调能安全返回；通过校准代数检查，防止上一次完成回调误删新一轮校准界面。
- 本项解决采集生命周期和卡住问题。语音有效性/纯静音识别、校准门阈值的前级增益补偿仍属于后续审核项。

### 4. 最终输出限幅

- [AudioEngine.cpp:25](../SSBVoiceProcessor/Source/AudioEngine.cpp#L25) 将末端链路调整为 `Band-Limit → Output Gain → Limiter`，限幅器看到的是滤波与输出增益后的实际信号。
- [LimiterNode.cpp:16](../SSBVoiceProcessor/Source/Nodes/LimiterNode.cpp#L16) 每个样本都计算允许的最大增益，避免旧增益已经压到阈值时，释放逻辑又把下一样本推过阈值；写回前再次约束样本到设定上限。
- [AudioEngine.cpp:195](../SSBVoiceProcessor/Source/AudioEngine.cpp#L195) 增加末端 0 dBFS 样本保护，位于输出电平统计和设备拷贝之前；即使总旁路或 Limiter 旁路，输出也限制在 `[-1, 1]`，非有限值变为静音。
- **行为说明：** Limiter 启用时遵守设定阈值；旁路时仍保留 0 dBFS 保护，超限信号会硬截断。这是样本峰值保护，不保证采样点之间的 true-peak 上限。
- 预设仍按节点名称匹配，参数 ID 未变；模块显示顺序随处理顺序改变。之前按数字索引保存的当前选中模块，首次打开可能切到相邻模块。

## 复现测试与使用范围

项目新增 `SSB_BUILD_TESTS` 选项，默认关闭，不改变正常发布构建流程。在 Windows 配置好 JUCE 和编译器后，可执行：

```text
cmake -B build-tests -DJUCE_DIR=D:/Dev/JUCE -DSSB_BUILD_TESTS=ON
cmake --build build-tests --config Debug
ctest --test-dir build-tests -C Debug --output-on-failure
```

本机使用的测试命令为：

```text
audit/tooling/venv/bin/cmake --build audit/build -j 4
audit/tooling/venv/bin/ctest --test-dir audit/build -C Debug -V
clang++ -std=c++17 -O1 -g -fsanitize=thread -I SSBVoiceProcessor/Source SSBVoiceProcessor/Tests/DisplayQueueTests.cpp -o audit/display_queue_tsan
audit/display_queue_tsan
```
