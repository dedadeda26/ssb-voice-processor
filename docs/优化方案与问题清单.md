## 1. P1：直接影响通联质量

### P1-1 带限斜率不足，邻近频道会被溅射

- **位置**：`Source/Nodes/BandLimitNode.cpp:36-46`（`makeHighPass` / `makeLowPass`，Q=0.707，各一阶二阶节）、`BandLimitNode.h:13-14`（默认 90 / 3100 Hz）。
- **实测**（`chain_analysis.py` 第 1、2 节，48 kHz，链路线性部分 = 高通 90 × 带限 90–3100）：

  | 频率 | 100 | 300 | 1000 | 2700 | 3100 | 4000 | 6200 | 8000 | 10000 |
  |---|---|---|---|---|---|---|---|---|---|
  | 衰减 dB | −4.4 | −0.1 | −0.0 | −2.0 | −3.0 | −5.9 | −13.0 | −18.0 | −22.9 |

  即 **12 dB/oct**。若换成 24 / 36 / 48 dB/oct，6.2 kHz 处分别是 −25.6 / −38.4 / −51.2 dB。

- **为什么会真的溅射**：饱和器在带限之前。两个音（2.7 + 3.0 kHz，−12 dBFS）经默认 +6 dB drive 后，带限输出在 3.1–6.2 kHz 仍残留 **−38.3 dBc**，6.2–12 kHz 为 −53.7 dBc；drive 提到 +12 dB 时是 **−27.6 / −43.0 dBc**（`chain_analysis.py` 第 4 节）。
  对 SSB 来说这是"音频道外"能量，电台自己的滤波不一定兜得住，尤其是用 SDR/直接变频时。
- **建议**：带限改为 LR4（24 dB/oct）起步、可选 LR8；或"2 阶 + 2 阶级联"保持相位可控。默认 300–2700 Hz（见 P2-3），并在饱和器后、带限前再补一级低通。

### P1-2 自动校准会覆盖 5 个无关模块的参数

- **位置**：`Source/AutoCalibrator.cpp:132-147`。分析只算出 `inputGain`、`gateThreshold`、`gateAmount`（`CalibrationAnalysis.h:60-79`），但提交时还额外写死：

  ```cpp
  setParam("High-Pass",   "cutoff",       100.0f);   // 覆盖用户设定
  setParam("Saturation",  "drive",          2.0f);   // 常量
  setParam("De-Esser",    "deEssAmount",   50.0f);   // 常量
  setParam("Limiter",     "limitThreshold", -2.0f);  // 常量
  setParam("Output Gain", "outGain",         -2.0f); // 常量
  ```

- **影响**：用户调好的音色（饱和量、去齿音量、限幅门限、输出电平）在点一次"自动校准"后被无提示重置；而且这些常量与本次采集到的电平**无关**，与"校准"语义不符。校准后 `markCustomPreset()` 还会把预设标成"自定义（未保存）"，用户保存的话等于把常量固化成新预设。
- **建议**：校准只提交分析出的 `inputGain` / `gate*`；其余模块不动，若确需保护性调整，先弹确认，或在 `Plan` 里加 `optional` 字段并只在分析有依据时提交。

### P1-3 参数与旁路都没有平滑，切预设/切模块/拖旋钮会咔哒

- **位置**：`Source/Nodes/InputGainNode.cpp:7-8`、`OutputGainNode.cpp:7-8`（每块直接乘新增益）；`DspNode.h:35`（`setBypassed` 只翻原子量）；`AudioEngine.cpp:274-275`（总旁路直接跳过整链）；`NodeCard.cpp:806`（旋钮直接 `pPtr->set()`）。
- **量化**：一次 +20 dB 的跳变在 waveform 中途可产生约 0.2 满量程的阶跃 → 明显 click；拖旋钮时每块刷新一次（512/48k ≈ 94 Hz 台阶）→ 轻微 zipper。切预设时 11 个节点的参数在同一块边界整体跳变，出现一次全程 click，且有"进电台的瞬时爆音"风险。
- **建议**：加 `SmoothedValue`/一阶 ramp：
  - 增益类参数（输入/输出/饱和 mix/makeup）——每样本或每块线性 ramp 到目标，时间常数 5–20 ms；
  - 旁路——在节点内部做 5–10 ms 等功率交叉淡化，旁路期间继续跑滤波器（保状态）或直接淡出后停算；
  - 预设加载——先在 `ScopedLock` 里置"静音 flag"，200 ms 内淡入，避免爆音。

### P1-4 多段压缩门限写死 −10 dBFS、无自动补偿增益

- **位置**：`MultiBandCompNode.cpp:92-97`（`threshold = threshBase - amount*0.30`，`ratio = 1 + amount*0.06`）、`:166-168`（三段 `threshBase` 都是字面量 `-10.0f`）、`:170-175`（只有全局 makeup，默认 0 dB）。
- **实测**（`dynamics_curves.py`）：

  | 频段电平 | amt 40 | amt 70 | amt 100 |
  |---|---|---|---|
  | −22 dBFS | 0.0 | 7.3 | 15.4 |
  | −10 dBFS | 8.5 | 17.0 | 25.7 |
  | −6 dBFS | 11.3 | 20.2 | 29.1 |

  对应门限/压缩比：amt 40 → **−22 dBFS / 3.4:1**；amt 100 → **−40 dBFS / 7:1**。

- **两个后果**：
  1. **"Amount" 实际上是音量旋钮**：调大 → 增益衰减 20–30 dB，而 makeup 默认 0，用户必须手动补回来。
  2. **频谱倾斜**：三段各自按本段电平压缩，语音低频段电平比 3–6 kHz 段高 10–20 dB，于是低频段被压 5–8 dB、高频段基本不动 → 越"用力"越薄越刺。实测同一时刻低频段 −14 dBFS（GR 5.6 dB）与高频段 −34 dBFS（GR 0 dB）相差 **5.6 dB 倾斜**。
- **建议**：把 `threshBase` 改成可调（或按 Input Gain 后的整体电平自适应），加自动 makeup（按三段 GR 的加权平均），并给三段加固定补偿偏移（例如 mid/high 相对 low 各 +X dB 门限），避免"用力变尖"。

### P1-5 托盘隐藏后再次启动，程序"看起来死了"

- **位置**：`Main.cpp:163`（`moreThanOneInstanceAllowed()` 返回 `false`）、`Main.cpp:84-91`（默认关闭行为 = 隐藏到托盘）、`Main.cpp:130-147`（只有托盘图标能重新显示窗口）。
- **原因**：单实例模式下第二次启动只把命令行转给已在运行的实例，然后自己退出；而 `SSBVoiceApplication` **没有重写 `anotherInstanceStarted`**，JUCE 的默认实现是空函数（`juce_Application.cpp:48`）。全工程唯一能把窗口重新显示出来的是托盘图标的 `showMainWindow()`。
- **影响**：用户点 X（默认隐藏到托盘）→ 再从开始菜单/桌面快捷方式启动 → 没有任何窗口、气泡或提示，进程本来就在跑。用户会以为程序卡死；只能去系统托盘（Win11 默认在折叠区）里找图标右键。
- **建议**：重写 `anotherInstanceStarted()` → 调 `mainWindow->setVisible(true); toFront(true);`；或在"隐藏到托盘"时弹一次气泡提示。

## 2. P2：局部失真、显示失真、性能

### P2-1 饱和器无过采样，高 drive 时有可闻带内混叠

- **位置**：`SaturationNode.cpp:11-16`，`std::tanh(dry*drive)*1/sqrt(drive)` 直接在设备采样率下算。
- **实测**（`chain_analysis.py` 3b 节，2.9 kHz 单音、带限之后的 1.0–1.6 kHz 杂散，17 次谐波 49.3 kHz 折叠到 1.3 kHz）：

  | 输入 | 0 dB | +6 dB | +12 dB | +18 dB | +24 dB |
  |---|---|---|---|---|---|
  | −12 dBFS | −225 | −228 | −172 | −102 | −57 dBc |
  | −6 dBFS | −231 | −172 | −102 | −57 | **−35 dBc** |

  默认 +6 dB、正常电平下可忽略（< −170 dBc）；但旋钮上限是 +24 dB，**高 drive + 高电平**时带内混叠到 −35 dBc，属于可闻的"砂纸感"。
- **建议**：2×/4× 过采样（`juce::dsp::Oversampling`）或 ADAA（一阶反正切抗混叠）；考虑把 drive 上限从 +24 收到 +15。

### P2-2 限幅器是"瞬时压 + 硬截"，无前视

- **位置**：`LimiterNode.cpp:17-23`（`gain = targetGain` 立即压，再用 `jlimit(-ceiling, ceiling)` 兜底）；`AudioEngine.cpp:279-280`（全局 `jlimit(-1,1)`）。
- **后果**：瞬态的第一拍没有预压，只能靠硬截断兜底 → 鼓/爆破音处产生方波式失真；且 0 dBFS 采样峰值保护不是 true-peak，SDR/数字链路下码间峰值仍可能过载。
- **建议**：加 2–5 ms 前视延迟 + 平滑释放；提供 4× 过采样 true-peak 上限；把 `jlimit` 保留为最后一道保险而不是主要手段。

### P2-3 默认 90 Hz 低切对 SSB 没有意义

- **位置**：`HighPassNode.h:11`（90 Hz）+ `BandLimitNode.h:13`（90 Hz）级联，共 24 dB/oct @90 Hz。
- **事实**：SSB 电台的发射通道通常 300 Hz 以下不辐射或不被利用，这部分能量只消耗 PEP、还可能触发 ALC。默认放 90 Hz 既不吃亏也无收益，反而让人误以为"低频很足"。
- **建议**：默认 150–250 Hz 低切（`README` 与实际默认值也需统一，上一轮 I2 提到但未落实）；把 90/100 Hz 保留为可选。

### P2-4 噪声门没有 hold 与迟滞，门限附近会抖

- **位置**：`NoiseGateNode.cpp:18-34`。包络用 5 ms/150 ms 一阶跟随，`envDb < thresh` 直接算目标增益，无 hold、无上下门限差。
- **后果**：语音尾巴和底噪交界处增益反复变化，出现"抽气/断续"；对 SSB 这种要长时间守听的场景比较明显。
- **建议**：加 Hold（50–200 ms）+ 迟滞 3–6 dB；把开门/关门时间做成独立的 4 个时间常数；或直接升级为 ratio 可调的降噪扩展器。

### P2-5 竖直电平表红段画在固定位置（明显显示错误）

- **位置**：`LevelMeter.cpp:88-96`。
  ```cpp
  float rH = fullH * (v - 0.90f);
  g.fillRect(inner.getX(), inner.getY(), inner.getWidth(), rH);  // 从顶端往下画
  ```
  绿段和黄段都是"从底部往上"堆的，红段却从 `inner.getY()`（顶端）往下画。`v=0.95` 时红段画在 95%–100%，应该在 90%–95%。结果是**表刚到 −5 dBFS 就已经顶到天花板**，视觉上像是满表。
- **建议**：改为 `y = bottom - v*fullH`、高度 `rH`（与 `NodeCard.cpp` 里水平版的写法一致）。

### P2-6 各模块的响应曲线基本都是解析近似，不是真实 IIR 响应

- **EQ**，`NodeCard.cpp:935-940`：
  ```cpp
  float lowShelf  = lowGain  / (1 + pow(f/lowFreq, 2));
  float midPeak   = midGain  * exp(-pow(log(f/midFreq)/log(2), 2));   // 高斯，与 midQ 无关
  float highShelf = highGain / (1 + pow(highFreq/f, 2));
  ```
  真实是 `makeLowShelf(Q=0.707)` / `makePeakFilter(Q=midQ)` / `makeHighShelf(Q=0.707)`。转折点上近似式给 `gain/2`，真实响应是 `gain/√2`（差 3 dB）；**`midQ` 完全没进公式**，拧 Q 曲线纹丝不动。
- **High-Pass**，`NodeCard.cpp:886-889`：`12*log10(2r/(1+r²))`，在 `r=0.5` 时给出 −1.9 dB，而真实的二阶巴特沃斯高通是 **−12.3 dB**；画的斜率约 6 dB/oct，实际是 12 dB/oct。
- **De-Esser**，`NodeCard.cpp:1136`：凹坑深度来自实时频谱与 `amount` 的乘积，不是真实的增益衰减。
- **建议**：直接用与音频相同的 `ArrayCoefficients` 算幅频（64 点求值即可），一处实现全部模块复用；既准确又不多写代码。

### P2-7 压缩器传输曲线忽略 knee

- **位置**：`NodeCard.cpp:1049-1050`（`inputDb <= thresh` 直角折线）；DSP 里 `CompressorNode.cpp:35-40` 有 6 dB 软拐点。
- **建议**：按同一段 smoothstep 公式画，用户才能对着曲线调 knee。

### P2-8 波形"平滑"用的是 2.7 秒前的样本

- **位置**：`VisualizationData.h:76-81`：`smoothedWave[slot]` 与 `wave[slot]` 是同一个环形槽位，`waveSize=131072`，48 kHz 下就是 **2.73 s 之前**的值，不是相邻样本。
- **建议**：改为对相邻样本做一阶平滑（或 peak-hold 抽取），若目的是"包络显示"就直接说明为包络。

### P2-9 显示路径的浪费

- `NodeCard.cpp:753-754`：只要当前模块有可视化，就 30 Hz `repaint()` 整张卡片（含瀑布图/曲线），旁路和无音频时也在画；
- `NodeCard.cpp:467-469`：每次 `paint()` 新建 3 个 `std::vector<float>(401)`；
- `AudioEngine.cpp:195-196`：每帧 FFT 里对 96 个频段做 192 次 `std::pow`（音频线程）；
- `NodeCard.cpp:702-709`：瀑布增益滑块每拖动一步就 `saveIfNeeded()` 写盘。
- **建议**：频段边界在采样率变化时预计算；曲线缓冲区做成成员复用；只在数据变化时重绘；设置写盘做 300 ms 去抖。

### P2-10 小的代码卫生问题

- `NodeCard.cpp:1133`：`static float smoothedSib` —— 画函数里的全局可变静态，跨实例共享且不在重建时清零；
- `AudioEngine.h:36,38`：`getInputRms/getOutputRms` 计算了但没人用；
- `CompressorNode`/`MultiBandCompNode`/`DeEsserNode` 的包络状态在旁路恢复时不重置，重新启用瞬间会带出旧的 GR。

### P2-11 风格预设之间没有电平一致性

- **位置**：`StylePresets.cpp:34-72`。四个风格只改 MBC Amount / 压缩比 / 饱和 drive，**从不改 makeup / Output Gain**。
- **后果**：按 P1-4 的曲线，风格 2（low 60）相对风格 1（low 40）在 −14 dBFS 上多压约 4 dB，风格 4 的 drive 又提到 +14 dB；切换风格时音量会明显跳变，用户只能自己用 Output Gain 追。
- **建议**：与 P1-4 一起做，风格里同时给出 makeup，让 4 个风格的输出电平差控制在 ±1.5 dB 内。

## 3. 界面状态一致性（UI 专项复核，均为 P2）

我另做了一遍界面/状态专项复核（音频线程实时性、SPSC 队列、回调生命周期这些上一轮修过的地方已复核为**干净**：回调内无锁、无分配、无消息线程调用；捕获缓冲的扩容/清零只在控制线程持锁做）。剩下的是"状态与显示"这一类：

| U3 | 风格下拉框只是"一次性命令"，不是状态 | `MainComponent.cpp:522-529` | 加载预设/重置后下拉框仍显示旧风格，重启后恒为"均衡" |

## 4. 建议增加的功能（针对 SSB 实际通联）

按"投入产出比"排序，前两项与已有代码结构契合度最高：

### F1 频谱降噪（NR），复用校准录下的底噪
- 现状只有向下扩展（"Noise Gate"），对稳态底噪（风扇、电源哼声、邻频噪声）只能整体关小，语音一进来噪声跟着进来。
- 校准已经强制采集 **2 秒纯底噪**（`AutoCalibrator` 前 25%），正好可以算一条噪声谱，做 Wiener / 谱减法，带过减因子和最大衰减限制（例如最多 −18 dB），并对增益做时间平滑避免"音乐噪声"。
- 预计新增 1 个节点 `SpectralNrNode`（FFT 1024、50% 重叠、Hann + 重叠相加），默认旁路，`docs` 里补算法说明。

### F2 慢速 AGC / 电平器
- 现在只有"一次性"的输入增益校准；换个坐姿、离麦远近变化，进台电平就变了。压缩器是快时间常数，补不了这个。
- 加一个慢速（1–3 s）RMS 电平器，把"到电台的电平"稳在目标值（例如 −12 dBFS RMS），并在电平表上标出目标区。

### F3 true-peak 限幅 + 4× 过采样
- 与 P2-1/P2-2 一起做：饱和器 4× 过采样、限幅器 4× 过采样 + true-peak 上限。数字链路（SDR、虚拟声卡）下码间峰值才不会超标。

### F4 显示"真实"响应
- EQ / 带限 / 去齿音的曲线改用真实 IIR 系数算幅频（P2-6/P2-7），并在带限卡片上标出"−40 dB 点"和实际带宽；这样用户能直接看到 P1-1 修复前后的差别。

### F5 一键自测
- 内置扫频 / 多音测试（离线跑一遍链路，输出频响、THD、混叠杂散、限幅超调），把本报告里的数值变成可复检的按钮，也方便以后回归。

## 6. 需要你确认的产品决策

1. **带限默认值**：改成 250–2900（典型 SSB 语音带宽）还是保持 90–3100 只加强斜率？我建议前者，但会改变现有听感。
2. **是否允许改变"校准"的语义**：我倾向"校准只动输入增益+噪声门"，其余保持用户设定（P1-2）。
3. **MBC 是否可以加门限旋钮**（当前只有 3 个 Amount + makeup），会改变界面布局；如果不想动 UI，我可以只做自动 makeup + 门限自适应。
4. **是否要 4× 过采样**：会多约 3–5% CPU（单声道 48 kHz 可忽略），换取混叠/true-peak 表现。
5. **是否需要 F1 频谱降噪**：这是新增模块，工作量最大，但对守听体验提升也最大。
